# TriRoute: карта модулів для переносу на Godot 4.7

Еталон — HTML-версія в `legacy/` (збирається `bash legacy/build.sh`, перевіряється тестами в `legacy/tests/`).
Нова версія — проєкт Godot у `godot/` (Godot 4.7, GDScript + C++ модуль `native/` для важких розрахунків, рендерер Forward+, лише ПК: Windows і Linux).

## Правила переносу

1. **Не гірше.** Кожен модуль переноситься з тим самим функціоналом і графікою не гіршою за HTML-версію.
   Модуль вважається готовим, лише коли його перевірено проти еталона:
   - логіка — тим самим сідом і тими самими сценаріями, що й тести `legacy/tests/`;
   - графіка — скріншотами з однаковою камерою (стара версія / нова версія).
2. **Детермінізм.** Той самий сід дає той самий світ, що й у HTML-версії. Для цього RNG (`Mulberry`) і шум (`Perlin`)
   перенесено біт у біт і покрито тестами (`godot/tests/test_core.gd`). Генератор світу має повторювати порядок
   викликів RNG оригіналу.
3. **Модулі незалежні.** Спілкуються через `EventBus` (сигнали) і стан у синглтонах; кожен має свої headless-тести
   (`godot --headless --path godot -s res://tests/run_tests.gd`).
4. **Можливості рушія — там, де вони дають виграш:** потоки (`WorkerThreadPool`) для генерації й пошуку маршрутів,
   `AStar2D` / власний A* на `PackedArray`, `MultiMeshInstance3D` для техніки й міток, GDShader для мапи,
   `Theme` для інтерфейсу, `ConfigFile` / JSON для налаштувань і збережень, `Timer` для автозбереження.

## Порядок і критерії готовності

| Етап | Що | Готово, коли |
|---|---|---|
| 1 | Модулі, `legacy/`, каркас Godot, ядро (RNG, календар, налаштування, збереження) | ✅ проєкт відкривається в Godot 4.4, headless-тести зелені |
| 2 | Генерація світу | **2а ✅** рельєф, суша, держави, решітка мапи (`TRWorldGen.generate`). **2б ✅** міста (назви, типи, населення), дороги, залізниці, порти, аеропорти, пункти пропуску (`TRWorldGen.generate_board`). Обидва — біт у біт з HTML на сідах 777, 303, 123456 (Linux і Windows). **2в ✅** характеристики держав (назви, кольори, населення, розвиток, ВВП, стабільність, лідери, закони, поклади, прапори) — `TRWorldGen.generate_states`, біт у біт; генератор міст бере населення від них |
| 3 | Рендер мапи + камера | **✅ основа мапи:** суша, вода з відблисками, кольори держав, тіні кордонів, рамка дошки, туман, камера з тим самим зумом, нахилом і плавністю (`shaders/map.gdshader`, `scripts/render/`). Порівняння з HTML за однакових кольорів і камери: середня різниця 0,05–0,2 з 255, відмінних пікселів 0,02–0,2% (`legacy/tests/mapshot.js` + `--shot`). Кольори держав — ті самі, що в HTML. Дороги, залізниці, сітка, стіни берегів, лінії кордонів і підписи — це оверлеї (етап 5) |
| 4 | Логістика + інциденти + економіка (без інтерфейсу) | headless-регресія 240 днів на 4 мапах: без помилок, кількість рейсів і гроші в межах ±10% від HTML. **4а ✅** старт компанії й біржа (`scripts/logistics/sim.gd`, частина 1). **4б ✅** ядро (частина 2): підбір техніки (`co_plan1`, `co_plan`), відправлення з пунктами пропуску (`TRWorldGen.crossings`), стан рейсу, доставка, повернення в хаб, місто, біржа, диспетчер, ціни пального й запчастин, ліцензії, місяць (зарплати, офіс, кредити, ринок праці, конфлікти, конкуренти, менеджери, досягнення, банкрутство). Біт у біт з HTML щодня протягом 150 днів: 2 світи × 3 сценарії (старт; автопарк рівня 2 з диспетчером; рівень 4 — міжнародні рейси й потяги) — `legacy/tests/simref.js` → `test_sim.gd`. Математика (`exp`, `log`, `log10`, `log2`, `pow`) — з правильним округленням (`TRMath`, `native/src/core/crmath.h`): однакова на Windows і Linux і збігається з Chromium. **4в ✅** інциденти (`scripts/logistics/sim.gd`, клас `Sim` поверх ядра `SimCore` у `sim_core.gd`): ДТП, поломки, штрафи ПДР, нестача пального, пошкодження вантажу, скасування замовником, крадіжки, пірати, збої GPS; пункти пропуску й митниця; закриті кордони, країни й КПП з об'їздом або поверненням вантажу; негода (зупинки, сповільнення, закриті порти); перекриття доріг; зони бандитів і піратів; закрите небо з обльотом; рішення гравця (`co_modal`: інтерфейс або фіксований вибір у тестах). Біт у біт з HTML усі 6 прогонів по 150 днів. Свідома відмінність: у HTML логіка кадру зайвий раз виконується з оновлення HUD, у Godot — рівно раз на кадр; випадковість, що в HTML бралася з `Math.random` (перекриття доріг, зони піратів), тут з другого генератора від сіда світу — гра відтворювана. Ще не перенесено: місячні події й тендери, ланцюжки й планувальник, збірні рейси, пошта |
| 5 | Оверлеї мапи | усе, що видно на мапі в HTML, видно і тут, скріншоти не гірші |
| 6 | Інтерфейс | усі вікна й дії HTML-версії доступні; стиль збережено |
| 7 | Звук, діагностика, решта | повна гра від старту до 7-ї ліцензії |

## Як перевіряти

- Godot (headless): `godot --headless --path godot -s res://tests/run_tests.gd`
- HTML-еталон: `bash legacy/build.sh`, далі тести Playwright з `legacy/tests/` (`node legacy/tests/cov.js run`).
